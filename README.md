# LANHub

A self-hosted web application for local networks and private internet access. Includes real-time chat, file sharing, multiplayer games, polls, feedback tracking, and a full admin panel — all running from your own hardware.

## Architecture Overview

```
Browser clients
    │
    ├── LAN clients ─────────────────────────────► Flask app (direct)
    │
    └── Remote clients ──► Cloudflare tunnel ────► Flask app
                                │
                    GitHub Pages redirector
                    (always points to current tunnel URL)
```

- **Flask + Flask-SocketIO** handles all HTTP and WebSocket traffic.
- **APScheduler** runs background jobs: stats broadcast (every 3s), GitHub redirector update (every 60s).
- **SQLite** (`app.db`) stores all persistent data.
- **configvars.json** is the single source of truth for all runtime configuration. Changes made via the admin panel are written to this file and hot-reloaded without restart.
- **start.sh** launches cloudflared, captures the tunnel URL, patches `configvars.json`, then starts Flask. It is not tracked by git — it is generated by `install.sh` on each machine.

## Quick Setup (Start Here)

### Step 1 — GitHub (browser, ~2 minutes)

These two actions require a browser and cannot be automated.

**1a. Create the redirector repository**

This is a GitHub Pages site that always points to your server's current address. Your friends bookmark this one URL and it always finds your server.

- Go to [github.com/new](https://github.com/new) and create a new **public** repository (e.g. `lanhub-redirect`)
- Check "Add a README file" so the `main` branch is created immediately
- Once created, go to **Settings → Pages → Source → Deploy from branch → main / (root) → Save**

**1b. Prepare to add your SSH key**

The installer will generate an SSH key and display it. You will need to paste it at [github.com/settings/ssh/new](https://github.com/settings/ssh/new). The installer pauses and waits for you to do this before continuing.

SSH is required so the server can push redirector updates to GitHub without storing credentials.

If you want to focus on developing, then this is optional as the installer will skip this once you've selected to install LANHub as a developer.

---

### Step 2 — Run the installer

Clone the repository and run `install.sh`. This is the only command you need.

```bash
git clone https://github.com/theplatecrafter/LANHub
cd LANHub
bash install.sh
```

The installer handles everything in sequence:

1. Installs system packages (`git`, `python3`, `python3-venv`, `python3-pip`, `curl`)
2. Creates the Python virtual environment and installs all dependencies from `dependencies.txt`
3. Installs `cloudflared` (the Cloudflare tunnel binary)
4. Generates an SSH key if one does not exist, displays the public key, and waits for you to add it to GitHub
5. Prompts for configuration: redirector repo URL, port, DEV admin credentials, visibility mode, access password
6. Writes `configvars.json` from your answers (using environment variable injection — safe for passwords with special characters)
7. Optionally disables system sleep and hibernation (recommended for a server)
8. Writes `start.sh` with the correct port from your config
9. Writes and enables the `systemd` service (`lanhub.service`) so the server starts on boot
10. Attempts an initial push to the GitHub Pages redirector

The installer is safe to re-run. It will prompt before overwriting `configvars.json` or an existing `lanhub` systemd service.

---

### Step 3 — Start the server

```bash
sudo systemctl start lanhub
```

The server is now running. On every subsequent reboot it will start automatically.

Confirm it is running:
```bash
sudo systemctl status lanhub
```

Within 60 seconds of startup, the GitHub Pages redirector will be updated with the current tunnel URL. Share the redirector URL with friends:
```
https://YOUR_USERNAME.github.io/lanhub-redirect/
```

The admin panel is available at `http://localhost:PORT/admin` using the DEV credentials you set during installation.

## Access Modes

The visibility mode is controlled from **Admin Panel → Access Settings** and takes effect immediately without a restart.

| Mode | `SITE_MODE` value | Behaviour |
|---|---|---|
| LAN Only | `lan_only` | Only connections from private/loopback IP ranges are allowed. Public connections (including Cloudflare tunnel requests, identified by the `CF-Connecting-IP` header) receive a 403 page with a direct LAN link. |
| Public with Password | `public_password` | All connections must present a valid HMAC-signed session cookie. Those without one are redirected to the password entry page. |
| LAN Free + Public Password | `both_password` | Connections from private IP ranges pass through freely. Public connections require the password. The password entry page also shows a direct LAN link for users who are physically on the same network but arrived via the tunnel. |

**Important:** "LAN" is determined server-side by the presence of the `CF-Connecting-IP` header and the IP address family. Any request arriving through the Cloudflare tunnel is treated as public regardless of where the client physically is. To connect as a LAN user you must use the direct `http://LAN_IP:PORT` address, not the redirector link.

**Session cookies** are HMAC-SHA256 tokens signed with the app's `SECRET_KEY`. Changing the access password immediately invalidates all existing cookies.

## How Public Access Works

LANHub uses a free Cloudflare quick tunnel (`cloudflared tunnel --url`) which requires no account, no port forwarding, and works behind any firewall including campus and corporate networks.

```
start.sh runs
    │
    ├── cloudflared starts, obtains a URL (e.g. https://xyz.trycloudflare.com)
    ├── URL is written to configvars.json as TUNNEL_URL
    │
    └── Flask starts
            │
            └── Scheduler fires within 60s
                    │
                    └── Pushes updated index.html to GitHub Pages redirector
```

The tunnel URL changes every time cloudflared restarts (i.e. on every server reboot). The GitHub Pages redirector is updated automatically, so the bookmarked link always works.

The redirector page embeds both the tunnel URL and the current LAN IP. When a visitor loads it, client-side JavaScript probes the LAN IP with a 2-second timeout. If the probe succeeds (visitor is on LAN), they are redirected directly to the LAN address — bypassing the tunnel and the password gate entirely. If it fails, they are sent to the tunnel URL.

Saving settings in **Admin Panel → Access Settings** triggers an immediate redirector push in a background thread rather than waiting for the 60-second scheduler interval.

Note: the redirector page is served over HTTPS (GitHub Pages). Due to browser mixed-content restrictions, the LAN probe fetch (`http://`) will silently fail on some strict browsers. In that case the visitor is redirected to the tunnel URL as a fallback — no broken experience, just no LAN shortcut.

## Server Management

| Action | Command |
|---|---|
| Start | `sudo systemctl start lanhub` |
| Stop | `sudo systemctl stop lanhub` |
| Restart | `sudo systemctl restart lanhub` |
| Status | `sudo systemctl status lanhub` |
| Live output | `journalctl -u lanhub -f` |

### Graceful shutdown sequence

When the server receives `SIGTERM` or `SIGINT` it performs the following before exiting:

1. Emits a `server_shutdown` socket event to all connected clients (browsers display a warning banner)
2. Stops the APScheduler
3. Pushes an offline page to the GitHub Pages redirector
4. Sends `SIGTERM` to the cloudflared process (PID stored at `/tmp/lanhub_cf.pid`)
5. Marks active Chess and UNO games as ended
6. Flushes all log handlers
7. Waits 1.5 seconds for in-flight socket messages and log writes to complete
8. Exits

## Updating

**From the admin panel:** Admin → Server → Update

Runs `git pull`, merges new keys from `configvars.example.json` into your `configvars.json` (your values are preserved), and runs `pip install -r dependencies.txt`. Output is streamed to the browser.

**From the terminal:**
```bash
sudo systemctl stop lanhub
git pull
sudo systemctl start lanhub
```

`start.sh` and `configvars.json` are excluded from git tracking and will never be modified by a pull. If a new version of `install.sh` changes the `start.sh` template, re-run `install.sh` to regenerate it.

## Logs

Log files are in the `logs/` directory. Each rotates at 5 MB with 3 backups kept.

| File | Contents |
|---|---|
| `logs/app.log` | General application events (startups, admin actions, game events) |
| `logs/access.log` | User-facing activity (messages sent, files uploaded, logins) |
| `logs/error.log` | Errors and exceptions only |
| `logs/github_sync.log` | All GitHub redirector push attempts and results |

```bash
tail -f logs/github_sync.log
journalctl -u lanhub -f   # full systemd journal including stdout
```

## Configuration Reference

All configuration lives in `configvars.json`. It is loaded at startup and hot-reloaded on writes without a restart. The admin config panel writes to this file directly.

`configvars.json` is not tracked by git. `configvars.example.json` is the authoritative template — new keys are merged in automatically on update.

| Section | Key | Description |
|---|---|---|
| `general` | `REPO_URL` | HTTPS URL of the GitHub redirector repository |
| `general` | `PORT` | Port Flask listens on |
| `access` | `SITE_MODE` | `lan_only`, `public_password`, or `both_password` |
| `access` | `SITE_PASSWORD` | Shared access password. Empty string disables the gate. |
| `access` | `SITE_ACCESS_COOKIE_DAYS` | Remember-me cookie lifetime in days |
| `access` | `TUNNEL_URL` | Current Cloudflare tunnel URL. Written by `start.sh` on each startup. |
| `admin` | `INITIAL_DEV_USERNAME` | Username for the first DEV account (seeded once on first run) |
| `admin` | `INITIAL_DEV_PASSWORD` | Password for the first DEV account |
| `admin` | `SECRET_KEY` | Flask session secret and HMAC key. Set to `__generate__` to auto-generate. |
| `scheduler` | `STATS_INTERVAL_SECS` | Stats broadcast interval in seconds |
| `scheduler` | `REDIRECTOR_INTERVAL_SECS` | GitHub redirector check interval in seconds |
